# BR-B — JavaScript Membership Advisor

## 한 줄 설명
JavaScript 개발자가 반복적인 포함 여부 검색을 구현할 때, 과제 10 논문에서 **직접 측정한 두 시나리오와 5개 데이터 크기**를 비교해 `Array.includes()`와 `Set.has()`의 관찰 결과를 확인하도록 돕는 웹앱입니다.

## 논문
**JavaScript 반복 검색에서 Array.includes와 Set.has의 성능 비교 — 배열 크기와 Set 생성 비용을 구분한 재현 가능 벤치마크**

## 논문에서 앱이 된 문장
이미 생성된 `Set`의 반복 검색은 실험한 모든 크기에서 빨랐지만, `Set` 생성 비용을 포함한 100회 검색에서는 10·100개에서 `Array.includes()`가 근소하게 유리했고, 1,000개 이상에서는 `Set` 생성 후 검색 방식이 유리했다.

## 이 앱이 돕는 사람과 하는 일
반복적인 포함 여부 검색을 구현하려는 JavaScript 개발자가 **논문에서 실제로 측정한 조건 안에서** 자료구조별 성능 차이를 바로 확인할 수 있게 돕습니다.

## 사용자가 할 일 3가지
1. `검색 자체 비교` 또는 `Set 생성 비용 + 100회 검색 비교` 중 논문의 실험 상황을 고른다.
2. 데이터 원소 수를 입력한다. 논문에서 실제 측정한 10 / 100 / 1,000 / 10,000 / 100,000일 때만 결과를 보여 주며, 다른 값은 측정 범위 밖이라고 안내한다.
3. **실험 결과 비교하기**를 눌러 두 방식의 실제 측정값과 관찰 결과를 확인한다.

## 실행 방법

### 브라우저에서 바로 실행
1. 저장소 또는 제출 ZIP을 새 폴더에 준비한다.
2. 루트의 `index.html`을 더블클릭한다.
3. 브라우저에서 바로 사용한다.

### Node.js로 실행
별도 npm 패키지 설치가 필요하지 않습니다.

```bash
npm start
```

기본 로컬 포트는 `10000`이며, Render에서는 `PORT` 환경 변수를 자동으로 사용합니다.

## Render 배포
이 저장소는 Render의 **Web Service + Docker** 배포를 바로 사용할 수 있도록 구성되어 있습니다.

1. Render에서 **New Web Service**를 선택합니다.
2. 저장소 `kjo35861/br-b-js-structure-advisor`를 선택합니다.
3. **Language: Docker**를 선택합니다.
4. **Branch: main**을 선택합니다.
5. **Root Directory**는 비워 둡니다.
6. 별도 Build Command / Start Command는 입력하지 않습니다.
7. **Deploy Web Service**를 누릅니다.

Dockerfile이 `node:22-alpine` 환경에서 `server.js`를 실행하며, 서버는 Render가 제공하는 `PORT`와 `0.0.0.0`에 바인딩됩니다.

## 앱이 실제로 사용하는 논문 데이터
| 원소 수 | Array 검색 중앙값(ns) | Set 검색 중앙값(ns) | Array 100회(ms) | Set 생성+100회(ms) | 생성비용 포함 100회 관찰 결과 |
|---:|---:|---:|---:|---:|---|
| 10 | 12.77 | 3.67 | 0.002188 | 0.002780 | Array.includes |
| 100 | 79.35 | 3.59 | 0.008438 | 0.008652 | Array.includes |
| 1,000 | 727.18 | 6.42 | 0.069918 | 0.034491 | Set.has |
| 10,000 | 7194.93 | 6.51 | 0.712055 | 0.500587 | Set.has |
| 100,000 | 76529.70 | 3.89 | 7.592631 | 5.905484 | Set.has |

## 논문 범위를 넘지 않도록 한 점
- 데이터 크기는 직접 입력할 수 있지만, 논문에서 측정하지 않은 값은 보간하거나 가장 가까운 실험값으로 추천하지 않고 `측정 범위 밖`이라고 안내합니다.
- 생성 비용 포함 비교는 논문과 동일하게 **100회 검색 조건**만 사용합니다.
- 앱 화면의 결과를 JavaScript 전체 환경의 절대적인 최적 선택이라고 표현하지 않고, **논문의 실험 조건에서 관찰된 결과**라고 표시합니다.

## 잘못된 입력 처리
빈 값·0·음수·소수는 입력 오류로 안내합니다. 1 이상의 정수라도 논문에서 측정하지 않은 크기라면 앱이 멈추거나 임의 추정하지 않고 `측정 범위 밖`이라고 안내합니다.
